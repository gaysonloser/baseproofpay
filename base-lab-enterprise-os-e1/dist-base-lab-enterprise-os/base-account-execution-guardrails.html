Base Account Execution Guardrails

A control surface for using Base Account sub-account architecture without quietly converting a user-controlled wallet into an automatic spending rail. The production account, app account, linked EOA and Vibenet assets each retain a different job.

Official SDK model verified · Manual funding default · No wallet request

Universal Base Account

Approval authority

Owns final, visible approval for any new production wallet action. It is never replaced by the app account or a linked EOA.

Application Sub Account

Execution isolation

Designed for app-specific agentic workloads, but CATVERSE keeps creation and funding manual until a separately scoped approval exists.

Linked EOA

Separate control plane

Can only send one owner-reviewed ordinary transaction at a time. It never represents the Base Account identity or a hidden batch sender.

Vibenet Recipient

Test-only assets

Holds test ETH, USDV and NFV for a future explicitly reviewed developer lifecycle. It never produces a mainnet, payment or ERP claim.

Read-only first

Before an optional app-account action, the only supported preflight is wallet_getSubAccounts with the Base Account and app domain. The method reads account state; it is not a request to create, fund or grant permissions.

  • Sub-account creation: manual.
  • Funding: manual.
  • Automatic Spend Permission: disabled by product policy.
  • ERP handoff: draft-only and human-reviewed when separately authorized.

This console cannot connect a wallet, create a sub account, request a spend permission, send a call, use a paymaster, or write to ERP.
